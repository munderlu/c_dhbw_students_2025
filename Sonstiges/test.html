🧠 C-Klausur Checkpoint

Frage 1: Der verlorene Speicher

Du reservierst Speicher mit int *p = malloc(sizeof(int)); und schreibst danach p = NULL;. Was ist das Problem?

Lösung anzeigen

Dies ist ein Memory Leak (Speicherleck). Da du die Adresse, die in p stand, mit NULL überschrieben hast, hast du keine Möglichkeit mehr, auf den reservierten Speicher zuzugreifen oder ihn mit free() freizugeben. Der Speicher bleibt bis zum Programmende belegt.

Frage 2: Die String-Falle

Was passiert hier: char name[4] = "Test"; printf("%s", name);?

Lösung anzeigen

Das Wort "Test" hat 4 Buchstaben. C benötigt aber ein 5. Zeichen für die Null-Terminierung (\0).
In name[4] ist kein Platz für die \0. printf wird also im Speicher über das Array hinaus weiterlesen, bis es zufällig irgendwo auf eine Null stößt. Das führt zu "Garbage"-Ausgaben oder einem Absturz (Segmentation Fault).

Frage 3: Pointer & Arrays

Ein int arr[] = {10, 20, 30, 40}; int *ptr = arr; ist gegeben.
Welchen Wert liefert *(ptr + 2)?

Lösung anzeigen

Der Wert ist 30.

ptr zeigt auf arr[0] (10).
ptr + 2 verschiebt den Zeiger um zwei Integer-Größen nach vorne (auf arr[2]).
Das * holt dann den Wert an dieser Stelle.

Frage 4: Call-by-Value vs. Reference

Wenn du eine Struktur an eine Funktion übergibst: void calc(struct Daten d). Kannst du das Original in der main ändern?

Lösung anzeigen

Nein. Das ist Call-by-Value. Es wird eine komplette Kopie der Struktur auf dem Stack erstellt. Änderungen betreffen nur die Kopie.
Für Änderungen am Original müsstest du einen Pointer übergeben: void calc(struct Daten *d).
